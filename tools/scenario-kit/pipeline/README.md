# Pipeline: двухэтапная обработка транскрибаций

Экономит 80-90% лимита при работе с длинными транскрибациями (1-2 часа).

## Как работает

```
Транскрибация (100k токенов)
    │
    ▼
Stage 1: Haiku — сжатие в конспект (10-15k токенов)
    │
    ▼
Stage 2: Sonnet — генерация сценария (5-8k токенов)
    │
    ▼
Готовый сценарий .md
```

Если транскрибация короткая (<15k слов / ~30 мин) — Stage 1 пропускается автоматически.

## Установка

Никаких зависимостей и API-ключей. Нужен только установленный **Claude Code CLI**
(команда `claude`) с активной подпиской — pipeline вызывает модели через
headless-режим `claude -p`, авторизация идёт по подписке.

## Использование

```bash
# Базовый запуск — сценарий по видео
python3 pipeline.py transcript.txt

# Указать выходной файл
python3 pipeline.py transcript.txt -o scripts/my-video/script.md

# Режим «по теме» с хронометражем
python3 pipeline.py topic_notes.txt --mode topic --duration 15

# Принудительное сжатие (даже для коротких текстов)
python3 pipeline.py transcript.txt --force-compress

# Из stdin (вставить текст напрямую)
cat transcript.txt | python3 pipeline.py -

# Без сохранения промежуточного конспекта
python3 pipeline.py transcript.txt --no-save-summary
```

## Что получаешь

1. **Сценарий** — в указанном файле или `pipeline/output/scenario_*.md`
2. **Конспект** — `*_summary.md` рядом со сценарием (промежуточный результат Stage 1)
3. **Статистика** — в консоли: сколько токенов потрачено, сколько сэкономлено

## Структура файлов

```
pipeline/
├── pipeline.py           # Основной скрипт
├── prompts/
│   └── compress.txt      # Промпт Stage 1 (сжатие)
├── output/               # Результаты (автосоздание)
└── README.md             # Этот файл
```

## Модели

| Этап | Модель | Зачем |
|------|--------|-------|
| Stage 1 | `claude-haiku-4-5` | быстрое сжатие транскрибации в конспект |
| Stage 2 | `claude-sonnet-5` | генерация сценария |

Вызовы идут через подписку Claude Code (headless `claude -p`), поэтому отдельных
затрат на API нет. Stage 1 сжимает входной текст в 5-10 раз → Stage 2 получает
меньше токенов на входе и работает быстрее.
