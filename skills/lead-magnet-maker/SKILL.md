# Скилл: Генератор лид-магнитов (бонусов)

## Когда использовать
Клиент говорит: «сделай лид-магнит», «создай бонус», «лид-магнит на тему…», «бонус для вебинара», «бесплатный материал», «раздатка», «PDF/HTML-гайд для воронки». Также вызывается оркестратором `producer-orchestrator` на Этапе 3 — лид-магнит по теме ролика.

Задача: собрать готовый **HTML лид-магнит** (3000-7000 слов) с промптами, инструкциями, кейсами — голосом клиента.

---

## Перед началом
1. Прочитай голос клиента: `~/packages/content-na-vibe/voice/author-voice.md`. Лид-магнит пишется от первого лица клиента, его тоном. Если файла нет — попроси оркестратора провести онбординг голоса.
2. Прочитай методичку и эталон (это канон формата — не изобретай свой):
   - `~/packages/content-na-vibe/tools/scenario-kit/knowledge/methodology-guide.md` — полный гайд: язык, метафоры, структура шагов, промпты, HTML.
   - `~/packages/content-na-vibe/tools/scenario-kit/knowledge/leadmagnet-reference.html` — эталонный HTML (тёмная тема, progress bar, шаги, prompt-block с копированием, чек-лист с localStorage, footer с CTA). Копируй из него дизайн и механику, **не контент и не ссылки** (там контакты автора курса — подставляй контакты клиента).
3. Узнай у клиента (через `AskUserQuestion`, если не знаешь): его соцсети и CTA-ссылку (Telegram-канал, YouTube) — для блока автора и footer. Не подставляй чужие контакты.

---

## Процесс

### Шаг 1 — Бриф (через `AskUserQuestion`)
1. Тема лид-магнита (по умолчанию — тема ролика от оркестратора).
2. Формат: A) Гайд с промптами · B) Чек-лист · C) Подборка инструментов · D) Кейс-стади.
3. Привязка: A) Бонус к мероприятию · B) Самостоятельный · C) Раздатка к ролику/уроку.
4. Объём: A) 3000 · B) 5000 · C) 7000 слов.

### Шаг 2 — Исследование
`WebSearch`: свежая статистика, кейсы, цены инструментов. Собери 5-7 конкретных цифр/фактов (в рублях, если про рынок РФ).

### Шаг 3 — Структура
Покажи клиенту оглавление-структуру, жди подтверждения.

### Шаг 4 — Генерация HTML (по эталону `leadmagnet-reference.html`)
Копируй из эталона дизайн (тёмная тема, CSS-переменные) и механику (JS), меняй контент. От первого лица клиента, разговорный тон, 5-7 цифр. Разбивай тему на **шаги 0..N** — по смысловым блокам (установка → использование → результат), как в methodology-guide.

Каждый шаг строится по паттерну:
- **метафора** (обязательна, бытовой образ — «.env это как сейф для секретных ключей»);
- инструкции пронумерованным списком;
- **промпт** (если есть) в `prompt-block` с кнопкой «Скопировать», самодостаточный, по структуре **РОЛЬ / КОНТЕКСТ / ДЕЙСТВИЕ / ФОРМАТ**;
- **ссылки-кнопки** на каждый упомянутый инструмент;
- callouts: 💡 Совет / ⚠️ Внимание / ✅ Результат.

### Шаг 5 — Обязательные блоки (как в эталоне)
1. Sticky header + бейдж + **progress bar** (заполняется по чек-листу).
2. Hero: заголовок + подзаголовок + stats (число шагов / промптов).
3. Шаги 0..N по паттерну выше.
4. Блок «Если что-то не работает» (FAQ Q/A).
5. **Чек-лист** внизу с `localStorage` (пункты = значимые действия, не по каждому шагу).
6. Footer с **CTA** и соцсетями клиента (из брифа), кнопка «наверх».
7. Дисклеймер, если упоминаются соцсети Meta*.

### Шаг 6 — Отдать
Сохрани файл, отправь клиенту тегом `[ФАЙЛ: путь]`.

---

## Дизайн
Один стандарт — эталон `leadmagnet-reference.html` (тёмная тема, акцент, progress bar). Дизайн не переизобретаем и не предлагаем выбор систем: копируем CSS и JS из эталона, меняем только контент. Если клиент явно просит другой стиль — предупреди, что это отступление от стандарта.

## Чек-лист
- [ ] Объём 3000-7000 слов, шаги 0..N по паттерну
- [ ] Метафора в каждом шаге
- [ ] 3+ prompt-block (РОЛЬ/КОНТЕКСТ/ДЕЙСТВИЕ/ФОРМАТ) с копированием
- [ ] 5+ цифр/фактов
- [ ] Ссылки-кнопки на инструменты, FAQ, чек-лист с localStorage, progress bar
- [ ] Footer: CTA + соцсети клиента (не чужие)
- [ ] Голос клиента, не шаблон
- [ ] Файл отправлен тегом `[ФАЙЛ: ...]`
