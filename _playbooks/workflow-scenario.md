# Два режима создания сценариев

## Режим 1: Сценарий по видео

**Вход:** ссылка на YouTube или текст транскрипции
**Промпт:** `youtube-scenario-kit/prompts/scenario.txt`
**Выход:** 6 блоков анализа + готовый сценарий для съёмки

> 💡 **Быстрый старт разбора чужого ролика — скилл `/video <url>`** (`~/.claude/skills/video/`):
> сам детектит тип ссылки, транскрибирует и вдобавок СМОТРИТ, что на экране (кадры по сменам
> сцен → `visual.md`), выдаёт разбор — и передаёт эстафету в этот воркфлоу (pipeline.py). Для
> скринкастов «глаза» полезны больше всего: команды/UI, которых нет в транскрипте.

Процесс:
1. Получить транскрипцию:
   - **Чужое видео (YouTube):** скачать субтитры через yt-dlp — обязательно свежий brew-бинарь и куки браузера, иначе «Sign in to confirm you're not a bot»:
     ```bash
     /opt/homebrew/bin/yt-dlp --cookies-from-browser chrome \
       --write-auto-subs --write-subs --sub-langs "ru-orig,ru" \
       --skip-download --convert-subs srt -o "transkrib/transcript_%(id)s" "URL"
     ```
     Детали и fallback, если субтитров нет (Deepgram), — в `transkrib/README.md`.
   - **Своя запись (локальный файл):** использовать `transcribe.py`
     ```bash
     python3 transcribe.py /путь/к/видео.mp4 -o scripts/{slug}/transcript.txt
     python3 transcribe.py /путь/к/видео.mp4 --timestamps -o scripts/{slug}/transcript.txt
     ```
     Требует: `DEEPGRAM_API_KEY` в `.env` (тот же ключ что в transcriber-bot).
     Требует: `ffmpeg` — `brew install ffmpeg`.
     Поддерживает: mp4, mov, m4a, mp3, wav, ogg, webm, mkv, avi, m4v.

     **Как работает внутри:**
     Видео-файл → ffmpeg извлекает аудио в MP3 64kbps/16kHz (~15-25 МБ вместо 200-500 МБ).
     Аудио стримится в Deepgram по частям → временный MP3 удаляется после отправки.
2. **ВСЕГДА** пропустить через pipeline (он сам решит — сжимать или нет):
   ```bash
   python3 youtube-scenario-kit/pipeline/pipeline.py transcript.txt -o scripts/{slug}/script.md
   ```
   Pipeline: Haiku сжимает транскрибацию → Sonnet пишет сценарий. Экономия ~70-80% лимита.
   Если текст короткий (<15k слов) — сжатие пропускается автоматически.

   > **Именование:** `script.md` — черновик из пайплайна. Финальный сценарий по стандарту
   > пакета (см. `file-routing.md`) живёт в `scripts/{slug}/scenario/scenario.md`.
3. Выдать результат (HTML через renderer или текстом)

## Режим 2: Сценарий по теме (с нуля)

**Вход:** тема + хронометраж + пожелания
**Промпт:** `youtube-scenario-kit/prompts/scenario_topic.txt`
**Выход:** готовый сценарий для съёмки

Процесс:
1. Уточнить: тема, формат (скринкаст/talking head/микс), хронометраж
2. Сгенерировать по промпту scenario_topic.txt
3. Выдать результат (HTML или текст)

## Факт-чек перед выдачей — ОБЯЗАТЕЛЬНО

**Правило:** каждое фактическое утверждение (цифры, цены, даты, названия, свойства инструментов) имеет источник — сессия, документация, транскрипт, скрин — или помечено `[УТОЧНИТЬ]`.

**Объёмные тексты** (сценарий 10+ мин, презентация, методичка, описание) — отдельный проход факт-чека ДО выдачи. Для больших текстов — субагент-факт-чекер: сначала whitelist проверенных фактов в `scripts/{slug}/facts.md` (факт → источник → статус), затем текст пишется ТОЛЬКО из whitelist. Готовый паттерн субагента — скилл `/niche-validator`.

**Два обязательных артефакта:**
1. **Секция «✅ ФАКТ-ЧЕК» в `scenario.md`** каждого ролика — что проверено вживую, что взято из источников, что осталось под `[УТОЧНИТЬ]`
2. **`scripts/{slug}/facts.md`** — для объёмных текстов: whitelist «факт → источник → статус», текст пишется только из него

**Эталон оформления** — секция «✅ ФАКТ-ЧЕК (проверено вживую)» в `scripts/✅ claude-code-besplatno/scenario.md`.

## После создания сценария — ОБЯЗАТЕЛЬНО спросить формат

> Сценарий готов! В каком формате тебе удобнее его использовать на съёмке?
> 1. **Sidebar** — Chrome-расширение с чек-листом сбоку экрана
> 2. **HTML** — интерактивный документ с таймером
> 3. **Текст** — оставить markdown как есть
> 4. **Презентация-навигатор** — HTML со sticky-оглавлением слева

Если **Sidebar** → вызови скилл `/sidebar-builder`.
Если **Презентация-навигатор** → создай `scripts/{slug}/navigator.html` по шаблону `navigator-presentation-kit/navigator-template.html` (полный стандарт — `knowledge/workflow-broadcast-presentation.md`):
- палитра брендбука: пергамент `#F5E6D0`, терракот `#E8762B`, графит `#1E1E1E`
- шрифты: Oswald (заголовки КАПС) + Press Start 2P (номера/теги) + Inter (текст) + JetBrains Mono (команды)
- sticky-сайдбар слева (графит): номер + эмодзи + название
- каждый блок = `<section>` с `height: 100vh` + `scroll-snap-align: start` (ровно один экран, без вертикального скролла — правило из `workflow-broadcast-presentation.md`)
- карточки команд — стилизованы под macOS-терминал
- **НЕ использовать** маркетинговые ярлыки — вместо них цветные полоски слева

## Формат сценария (блок)

Сценарий — **шпаргалка для съёмки БЕЗ суфлёра**, не текст для зачитывания.

```
⏱ БЛОК: [Название] — [X мин] [на камеру / экран / камера → экран]

Ключевые смыслы (что ОБЯЗАТЕЛЬНО сказать):
• Смысл 1 — короткая фраза
• Смысл 2 — короткая фраза

Опорные точки (порядок мыслей):
1. Начни с [тема] → [ключевая фраза]
2. Потом [тема] → [ключевая фраза]

🪝 Open loop (врезка после блока):
«Точный текст с curiosity gap»
→ Закрывается в: [блок X]

🔗 Переход к следующему блоку:
«Связующая фраза»

⚠ Адаптировать: [что заменить на своё]
```

## Принципы сильного сценария

1. **Story arc** — история, не лекция: боль → решение → доказательство → трансформация
2. **Show, don't tell** — минимум 1 блок живого демо (30-40% хронометража)
3. **Сильные open loops** — минимум 3 на ролик, с curiosity gap
4. **Минусы растворять** — нет отдельного блока «подводные камни»
5. **Эмоциональный финал** — итог → трансформация → мягкая воронка → open loop на следующий ролик
6. **Retention-проверка** — каждый блок: «почему зритель НЕ переключит?»

## Правила формата

- ХУК: максимум 4-5 опорных точек
- 2-4 ключевых смысла в каждом блоке
- Хронометраж у каждого блока + пометка [камера/экран]
- Open loops — минимум 3 на ролик
- Воронку упоминать не более 2 раз за ролик (краткий анонс лид-магнита в хуке — «досмотри до конца, дам методичку» — касанием НЕ считается)
- Пол: мужской
- Сумма блоков ≈ заданный хронометраж (±10%)

## 🎟 Приглашение на бесплатный практикум — ОБЯЗАТЕЛЬНО в каждом суфлёре

**Правило:** в **каждом** `teleprompter.md` (и `teleprompter.html`) должно быть приглашение на бесплатный практикум, размещённое в диапазоне **3–5 минута ролика** (по тексту, а не в начале и не в финале). Это мягкая мид-ролл врезка, а не финальный CTA.

**Перед тем как финализировать суфлёр — ВСЕГДА спрашивай автора:**
1. На какой практикум / эфир зовём в этом ролике?
2. Дай ссылку (рег-страница) — чтобы я вытащил название и смыслы и встроил их в текст.

Если ссылки/названия пока нет — оставляй **пустые места-плейсхолдеры**, которые автор впишет сам:
```
> 📌 ВПИШИ ПЕРЕД СЪЁМКОЙ: [название практикума] + [когда] + [куда идти — ссылка в описании/закреп]
```
и в самом тексте — `[«___название___»]` и `[ссылка]`.

**Как писать врезку:**
- Привязать к теме ролика (естественный мостик от того, что зритель только что узнал, к «а на практикуме научишься делать это по-настоящему»).
- Мягко, по-человечески, ~30–40 секунд. Не «продающий блок», а дружеская рекомендация.
- Подчеркнуть, что **бесплатно** и живой формат, назвать 1-2 конкретные выгоды/бонуса с рег-страницы.
- Отдельный блок в суфлёре, например `## БЛОК N.5 — ПРИГЛАШЕНИЕ НА ПРАКТИКУМ · [на камеру]`.

**Где НЕ должно быть:** в `navigator.html` (презентация для зрителя остаётся чистой — врезка живёт только в суфлёре и в `scenario.md` как блок). Финальный лид-магнит в конце ролика — это отдельная история, он не отменяет мид-ролл приглашение на 3–5 минуте.

**Воронка-лимит:** приглашение на практикум считается одним из ≤2 упоминаний воронки за ролик (см. «Правила формата»). Стандартная раскладка: мид-ролл практикум + финальный лид-магнит = ровно 2; краткий анонс лид-магнита в хуке касанием не считается. Не пересаливать.

## Итерации (что можно просить после сценария)

- «Переделай хук» — переписать вступление
- «Добавь свои open loops» — вставить крючки под конкретную воронку
- «Подробнее блок про X» — развернуть конкретный раздел
- «Сделай короче / длиннее» — изменить хронометраж
- «Добавь скринкаст-инструкцию» — пошаговые действия на экране
- «В моём стиле» — усилить авторский голос
