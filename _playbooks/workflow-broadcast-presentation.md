> Стандарт оформления `navigator.html` для каждого YouTube-ролика. Это слайдовая презентация, которую автор транслирует зрителям во время записи: они видят буллиты, инсайты, цитаты и сравнительные таблицы.

> ⚠️ **Для YouTube-съёмок актуален стандарт v2** (см. следующий раздел). Эталон v2: `scripts/claude-workflows-orkestr/navigator.html`. Дизайн-система и типы слайдов из этого файла остаются базой; лейаут слайда и место шпаргалки ведущего в v2 заменены.

Решение автора: «теперь используем такой дизайн в презентациях именно для ютуба». Это **датированная замена** стандарта, а не второй параллельный вариант.

### 1. Лейаут 75/25: сцена + шпаргалка

Каждый слайд — CSS grid `75fr 25fr`:

- **Левые 75% (`.stage`)** — контент для зрителей.
- **Правые 25% (`.cheat`)** — колонка «ШПАРГАЛКА» для ведущего: реплики из `teleprompter.md`, готовые к произнесению (`.cue` — курсив, ключевые слова подсвечены `<b>` терракотом); внизу футер `.cheat-next` «→ следующий слайд: …»; врезки-CTA — `.cue.director` с меткой 🎬 (пунктирная терракотовая рамка).
- Граница зон — **контрастная линия реза** (`border-left: 3px solid var(--terracotta)` у `.cheat`). автор кропит экран по этой линии — **зрители шпаргалку НЕ видят**.

**Старый принцип «navigator — контент для зрителя, не шпаргалка ведущего» НЕ нарушен:** зритель по-прежнему видит только контент. Изменилась механика — шпаргалка живёт в обрезаемой зоне того же файла, а не в отдельном teleprompter. Опенлупы в зрительской зоне (75%) по-прежнему запрещены; в шпаргалке — разрешены (зритель их не видит).

### 2. Editorial-стиль левой зоны

- **Kicker** капсом с оранжевым тире: «ПРИНЦИП 01 ——» (Press Start 2P + `::after`-полоска терракотом)
- **Огромный заголовок** в 1–2 строки (Oswald ~4rem и больше): белый + ключевое слово оранжевым (`<span class="hl">`)
- **Двухколоночное тело** `.body-grid`: слева экспонат, справа буллиты `.point` с жирным лид-ином (`<strong>Суть:</strong> расшифровка`)
- **Плашки «💡 Про-тип»** (`.protip`) — один инсайт-совет внизу слайда
- Палитра и шрифты — прежний «Крафтовый терминал» (Oswald / Press Start 2P / Inter / JetBrains Mono; терракот, графит, пергаментные оттенки)

### 3. Экспонаты — HTML-мокапы кодом, НЕ скриншоты

Всё, что «показываем», собирается вёрсткой: чат-пузыри, окна терминала со светофором (`.window` + `.wdot r/y/g`), схемы fan-out (`.fan`), стат-карточки с гигантскими цифрами (`.stat-num`). Скриншоты в слайды не вставлять.

### 4. Человеческий язык

Зритель должен узнать свою задачу. Абстракции переводить в бытовые примеры, жаргон запрещён (см. память `feedback_simple_language`: «хирургия» → «меняй только то, что просил»).

### 5. Факт-чек перед сборкой

До сборки слайдов составить whitelist проверенных фактов: `scripts/{slug}/facts.md` или секция «✅ ФАКТ-ЧЕК» в `scenario.md`. Текст слайдов берётся **только** из whitelist — цифры и утверждения вне его в слайды не попадают.

### 6. Проверка: без скролла, headless-браузером

Каждый слайд (включая колонку шпаргалки) обязан влезать без вертикального скролла. Проверка — headless-браузер (Playwright/Chromium) на 1920×1080: пройтись по всем слайдам и убедиться, что контент не переполняется. Плюс все прежние проверки стандарта (см. «Один экран = один слайд» ниже).

### 7. Gift-слайд в финале

Если у ролика есть лид-магнит (по умолчанию — есть) — слайд «🎁 Забирай в Telegram» с карточками содержимого лид-магнита. Образец: `scripts/✅ claude-code-besplatno/navigator.html`, слайд 09.

## Цель формата

`navigator.html` это контент для зрителя, не шпаргалка для ведущего:

- Зритель видит структуру урока на экране
- Ключевые цифры, цитаты и кейсы — крупно, чтобы воспринимались с трансляции
- Сравнения «было/стало» — двумя колонками, без листания PDF
- Финальные инсайты — отдельными слайдами на полный экран

**Что НЕ должно попадать в презентацию:**

- Open loops для удержания зрителя («сейчас покажу...», «через 5 минут...»)
- Метки времени блоков ролика (1.5'', 4'') — это для съёмки, в `teleprompter.html`
- Метки переключения камера/экран
- Карточки «⚠ Адаптировать» с инструкциями ведущему
- Внутренние пометки для съёмки

Если в сценарии есть open loop или техническая подсказка — она остаётся в `scenario/scenario.md` и `teleprompter`, в `navigator.html` идёт только смысл.

> ⚠️ **v2 (2026-07-04):** принцип действует, но только для **зрительской зоны** (левые 75%). Реплики ведущего, опенлупы и CTA-врезки в v2 живут в колонке-шпаргалке того же файла — зритель её не видит, потому что она обрезается кропом. См. раздел «Стандарт v2» выше.

## Типы слайдов и их шаблоны

### 1. Титульный слайд

Огромная цифра (43.000 / 65 / 8 фишек) + название ролика + подзаголовок + пиксельный тег `@example`.

```html
<section class="slide" data-slide="1">
  <div class="slide-tag">@YOUR_CHANNEL</div>
  <div class="slide-inner text-center">
    <div class="hero-num">43.000</div>
    <div class="hero-num-suffix">установок за неделю</div>
    <div class="hero-title">Один файл, который меняет Claude Code</div>
    <div class="hero-subtitle">4 принципа от Андрея Карпати</div>
    <div class="hero-pixel-tag">CLAUDE.MD · 65 СТРОК</div>
  </div>
</section>
```

### 2. Слайд с буллитами

3-5 пунктов с пиксельными цифрами (01/02/03) или эмодзи в круге. На белой карточке с терракотовым бордером слева.

Используется для планов («Сегодня три вещи»), описаний автора, перечислений артефактов.

### 3. Слайд-принцип

Большая цифра принципа (Press Start 2P, 8rem) + название (Oswald 6rem) + tagline + терракотовая карточка с формулировкой «📝 ЗАПОМНИ».

```html
<div class="principle-hero">
  <div class="principle-num">01</div>
  <div class="principle-name">Думать перед<br>кодом</div>
  <div class="principle-tagline">Claude по умолчанию НЕ думает...</div>
</div>
<div class="principle-card">
  <strong>Сначала думай, потом пиши.</strong><br>
  Несколько интерпретаций → выбор → план → код.
</div>
```

### 4. Слайд-цитата (тёмный)

Класс `slide.dark`. Тёмная карточка с большим открывающим « + цитата (Oswald 3rem курсив) + автор моноширинным внизу справа. Самые сильные цитаты выделять `accent-light` на ключевых словах.

### 5. Слайд-кейс (двухколоночный)

Промт зрителя сверху → две колонки `case-side.bad` (красный бордер) и `case-side.good` (зелёный бордер). В каждой колонке: метка «❌ ЧТО ДЕЛАЕТ» / «✅ ЧТО ДОЛЖНО БЫТЬ» + headline + 4-6 буллитов.

Используется для всех демонстраций «было/стало», особенно для кейсов из источников типа `EXAMPLES.md`.

### 6. Слайд с командой (терминал)

Mac-style терминал с тремя точками + JetBrains Mono тело. Подсветка `cmd` (терракот), `arg` (голубой), `dim` (серый), `green` (✓ done).

Используется для команд установки, промтов, конфигов.

### 7. Сравнительная таблица

`compare-table` с тёмной шапкой. Метрика слева, варианты справа. Класс `bad`/`good`/`neutral` на ячейках для подсветки направления.

### 8. Акцентный слайд (терракотовый)

Класс `slide.accent` — фон-градиент терракот → терракот-тёмный. Используется для главных выводов или вступлений к секциям («3 способа поставить файл»).

### 9. Финальная цитата

Тёмный слайд + `final-quote-card` с гигантской открывающей кавычкой (Oswald 14rem) + цитата (Oswald 4.5rem) + атрибуция моноширинным внизу.

### 10. Слайд лид-магнита

3 `gift-item` с иконкой в терракотовом квадрате + название + описание. Снизу `gift-cta` тёмный блок с CTA-фразой.

## Технические правила

### 🔴 Один экран = один слайд, БЕЗ вертикального скролла (КРИТИЧНО)

Каждый экран справа ОБЯЗАН помещаться целиком, без вертикальной прокрутки. На трансляции зритель видит экран целиком — листать его нельзя. Скролл внутри экрана = брак.

```css
html { scroll-snap-type: y mandatory; }
.slide { height: 100vh; scroll-snap-align: start; scroll-snap-stop: always;
         display: flex; flex-direction: column;
         justify-content: center; justify-content: safe center; /* safe — чтобы при переполнении не обрезался верх */
         overflow: hidden; }
```

> ⚠️ **v2 (2026-07-04):** `.slide` — это grid `75fr 25fr`, а flex-центровка с `safe center` переезжает на левую зону `.stage`. Правило «один экран, переполнение не скроллится» действует для ОБЕИХ зон, включая шпаргалку. Проверка в v2 — headless-браузером (Playwright/Chromium) на 1920×1080, не только глазами.

- Именно `height: 100vh` (НЕ `min-height` — иначе контент перельётся и появится скролл). Переполнение НЕ скроллится.
- **Обязательно `justify-content: safe center`** (вторая строка — фолбэк для старых браузеров): без `safe` переполненный слайд обрезается с ОБОИХ концов и заголовок молча исчезает. С `safe` контент прижимается к верху — переполнение видно сразу.
- **Лимит на один экран:** ~3–4 карточки ИЛИ одна таблица ИЛИ заголовок + подзаголовок + 1 крупный элемент. Больше — не влезет.
- **Контента в разделе много → дели на НЕСКОЛЬКО экранов-страниц внутри одного раздела.** Пункт меню один, экранов под ним 2–3. Никогда не запихивай всё в одну длинную скроллящуюся секцию.
- Правило действует и для **формата с боковым меню**: sidebar слева + scroll-snap-слайды справа, каждый = ровно один экран. Меню ведёт на первый экран раздела, scroll-spy подсвечивает текущий раздел.
- Проверка перед сдачей: открыть в браузере (в том числе в НЕвысоком окне ~800px), прокрутить — на каждом шаге виден ОДИН цельный экран, полосы вертикального скролла нет, **у каждого слайда виден его номер (slide-tag) и заголовок**.

### Навигация

- **Прогресс-бар сверху** (`progress-track` + `progress-fill`) — терракотовый градиент, заполняется по мере прокрутки
- **Счётчик внизу справа** — пиксельный, формат «05 / 26»
- **Стрелки внизу слева** — круглые тёмные кнопки ← →
- **Хоткеи:** ↓ → Space PageDown — следующий, ↑ ← PageUp — предыдущий, Home / End — край, F — полный экран

### Scroll-reveal — анимация появления слайдов (v2, 2026-07-04)

При листании каждый слайд **оживает**: элементы левой зоны `.stage` выезжают снизу по очереди (сначала крупные блоки, потом карточки/шаги внутри). Шпаргалку `.cheat` НЕ трогаем — она видна всегда. Механизм — `IntersectionObserver` вешает класс `.reveal`, когда слайд появляется на экране, и снимает при уходе (анимация играет заново при каждом возврате). Никаких библиотек — чистый CSS + ~12 строк JS, встроены прямо в файл. Уважает `prefers-reduced-motion`.

CSS (в `<style>`, после медиа-запросов адаптации):

```css
/* SCROLL-REVEAL — анимируем только левую зону .stage, шпаргалку .cheat не трогаем */
.stage-inner > * { opacity: 0; transform: translateY(28px);
  transition: opacity .6s cubic-bezier(.16,1,.3,1), transform .6s cubic-bezier(.16,1,.3,1); }
.slide.reveal .stage-inner > * { opacity: 1; transform: none; }
.slide.reveal .stage-inner > *:nth-child(1) { transition-delay: .05s; }
.slide.reveal .stage-inner > *:nth-child(2) { transition-delay: .18s; }
.slide.reveal .stage-inner > *:nth-child(3) { transition-delay: .32s; }
.slide.reveal .stage-inner > *:nth-child(4) { transition-delay: .46s; }
.slide.reveal .stage-inner > *:nth-child(5) { transition-delay: .60s; }
.slide.reveal .stage-inner > *:nth-child(6) { transition-delay: .74s; }
/* Уровень 2 — карточки/шаги/буллиты внутри появляются каскадом после родителя */
.stage-inner .flow > *, .stage-inner .duo > *, .stage-inner .points > *, .stage-inner .body-grid > * {
  opacity: 0; transform: translateY(22px);
  transition: opacity .55s cubic-bezier(.16,1,.3,1), transform .55s cubic-bezier(.16,1,.3,1); }
.slide.reveal .stage-inner .flow > *, .slide.reveal .stage-inner .duo > *,
.slide.reveal .stage-inner .points > *, .slide.reveal .stage-inner .body-grid > * { opacity: 1; transform: none; }
.slide.reveal .stage-inner .flow > *:nth-child(1), .slide.reveal .stage-inner .duo > *:nth-child(1),
.slide.reveal .stage-inner .points > *:nth-child(1), .slide.reveal .stage-inner .body-grid > *:nth-child(1) { transition-delay: .55s; }
.slide.reveal .stage-inner .flow > *:nth-child(2), .slide.reveal .stage-inner .duo > *:nth-child(2),
.slide.reveal .stage-inner .points > *:nth-child(2), .slide.reveal .stage-inner .body-grid > *:nth-child(2) { transition-delay: .70s; }
.slide.reveal .stage-inner .flow > *:nth-child(3), .slide.reveal .stage-inner .duo > *:nth-child(3),
.slide.reveal .stage-inner .points > *:nth-child(3) { transition-delay: .85s; }
.slide.reveal .stage-inner .flow > *:nth-child(4), .slide.reveal .stage-inner .points > *:nth-child(4) { transition-delay: 1.0s; }
.slide.reveal .stage-inner .flow > *:nth-child(5) { transition-delay: 1.15s; }
@media (prefers-reduced-motion: reduce) {
  .stage-inner > *, .stage-inner .flow > *, .stage-inner .duo > *,
  .stage-inner .points > *, .stage-inner .body-grid > * {
    opacity: 1 !important; transform: none !important; transition: none !important; } }
```

JS (отдельным `<script>` перед `</body>`, после скрипта навигации):

```html
<script>
(function () {
  const io = new IntersectionObserver((entries) => {
    entries.forEach((e) => e.target.classList.toggle('reveal', e.isIntersecting));
  }, { threshold: 0.55 });
  document.querySelectorAll('.slide').forEach((s) => io.observe(s));
})();
</script>
```

> Это часть эталонного `<style>`/скриптов v2 — при копировании из `scripts/claude-workflows-orkestr/navigator.html` анимация переносится автоматически. Проверка headless-браузером: снять кадр сразу после перехода на слайд (часть элементов ещё не появилась) и через ~1.4 с (все на месте).

### Метки слайда

Каждый слайд начинается с `slide-tag` в верхнем левом углу — пиксельный шрифт, типа `02 · АВТОР` или `КЕЙС ИЗ EXAMPLES.MD · DRIVE-BY REFACTORING`. Это для зрителя — он понимает где находится.

### Адаптация

Один media query на 1200px (одноколоночные кейсы), второй на 768px (мобильная урезанная типографика). Презентация оптимизирована под десктоп/OBS. Помни: из-за `height: 100vh + overflow: hidden` контент, не влезший на узком экране, обрезается — если слайд плотный (двухколоночный кейс), проверь его в окне 1200px; не влезает — дели на два слайда, а не полагайся на «в одну колонку сложится».

### Inline-стили

**Запрещены полностью.** Если нужна разовая стилизация — добавляй utility-класс в `<style>` и используй его. IDE-линтер ловит inline.

## Типовая структура слайдов ролика

Объём презентации — 20-30 слайдов на ролик длиной 12-15 минут. Типовой расклад:

| Группа | Кол-во слайдов | Что включить |
|--------|---------------|--------------|
| Открытие | 3-4 | Титул + автор/контекст + план + ключевая цифра |
| Контент-блок 1 (например «4 принципа») | по 2-3 на пункт | Принцип-слайд + цитата (если есть) + кейс/пример |
| Контент-блок 2 (например «3 способа») | 4-5 | Вступление + по слайду на каждый способ + сравнение |
| Тест/демо | 2-3 | Постановка + результат + инсайт |
| Бонус | 1-2 | Универсальность / расширение применимости |
| Закрытие | 3 | Главный вывод + финальная цитата + CTA-лид-магнит |

Итого: 20-30 слайдов.

## Чек-лист перед сборкой нового navigator.html

Пункт про опенлупы читать как «убрать из зрительской зоны» — в шпаргалке они разрешены.

- [ ] Скопировать блок `<style>` из `navigator-presentation-kit/navigator-template.html` целиком (не переписывать дизайн-систему)

- [ ] Каждый кейс «было/стало» — отдельный слайд с двумя колонками
- [ ] Главный вывод и финальная цитата — на полный экран, в конце

## Связь с другими файлами в папке ролика

```
scripts/{slug}/
├── transcript.txt          ← оригинал источника (если разбор чужого)
├── scenario/scenario.md    ← полная архитектура: open loops, тайминги, демо
├── teleprompter.md         ← разговорный текст для съёмки
├── teleprompter.html       ← HTML-телесуфлёр с автопрокруткой
├── navigator.html          ← ЭТА презентация для трансляции зрителям
└── animation/              ← (опц.) анимированные слайды для монтажёра: full/ mp4 + layers/ PNG + poster/ + README
```

> `animation/` собирается движком `tools/slide-animator/` (`./render.sh {slug}`), который **автогенерирует композиции из этого же `navigator.html`**. ⚠️ Гейт: движок запускать только после согласования `navigator.html` автором и только один раз — сначала спросить «делать анимацию?». Полностью — `workflow-postproduction.md` → «Анимация слайдов» → «Процесс-гейт».

Каждый файл — для своей задачи:

| Файл | Кому | Когда |
|------|------|-------|
| `scenario/scenario.md` | автору (планирование) | Перед съёмкой при подготовке |
| `teleprompter.md` | автору (читка) | Во время съёмки на втором экране |
| `teleprompter.html` | автору (автопрокрутка) | Альтернатива .md, удобнее визуально |
| `navigator.html` | **Зрителям** (трансляция) | Транслируется в OBS как источник |
