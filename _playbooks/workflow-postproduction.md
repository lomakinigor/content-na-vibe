# Workflow постпродакшена (после съёмки видео)

## Этап 1: Транскрибация и анализ обещаний

```bash
# 1. Транскрибировать видео
python3 transcribe.py /путь/к/видео.mp4 --timestamps -o scripts/{slug}/transcript.txt

# 2. Вытащить все обещания и обязательства из транскрибации
# Скорми транскрибацию в Claude вместе с промптом:
# youtube-scenario-kit/prompts/extract_promises.txt
```

**На выходе:** файл `scripts/{slug}/promises-analysis.md` с разделами:
- 🤝 Обещания — всё что пообещал зрителям
- 🔗 Сервисы — ссылки и сервисы из видео
- 🎁 Лид-магниты — что предлагаешь зрителям
- ⚠️ Условия — требования и ограничения
- 📅 Будущие видео — анонсы других роликов
- 📝 Воронка — основная последовательность (видео → Telegram → практикум)
- 🚨 Вырезаемые части — куски для монтажа (если есть пометки в видео)
- ✅ Чек-лист для постпродакшена

Этот файл — **основа для всех последующих шагов**.

## Этап 2: Рекомендации по контенту

После анализа обещаний предлагаю:

1. **Для YouTube описания:** все ссылки, лид-магнит, таймкоды
2. **Для Telegram-поста:** главное обещание, промпты/шаблоны, CTA
3. **Для монтажа:** паузы, технические моменты для вырезки

## Этап 3: Создание контента

**Опция А: Telegram-пост** — из promises-analysis → структура: заголовок → основное → промпты/ссылки → CTA
**Опция Б: YouTube описание** — SEO-описание + таймкоды + все ссылки
**Опция В: Оба** — полный набор для публикации

**Факт-чек перед выдачей любого текста** (описание, пост, конспект, методичка) — ОБЯЗАТЕЛЕН: каждый факт — источник или `[УТОЧНИТЬ]`. Правило и артефакты — `knowledge/workflow-scenario.md` → «Факт-чек».

## Workflow создания ролика (10 шагов)

1. **Идея** → записать в `ideas/backlog.md`
2. **Проработка** → определить режим (по видео / по теме)
3. **Сценарий** → запустить промпт → `scripts/{slug}/script.md` (черновик; финал — `scenario/scenario.md`, см. file-routing.md)
4. **Аудит** → проверить по документации (audit.md)
5. **Итерации** → доработать хук, open loops, блоки, голос автора
6. **Финал** → переписать в `scripts/{slug}/ready-for-filming/{slug}.md`
7. **Формат для съёмки** → спросить: Sidebar, HTML, текст или навигатор?
8. **Метаданные** → заголовок, описание, теги, превью
9. **Съёмка** → по выбранному формату
10. **Публикация** → обновить GOALS.md, записать выводы

## Анимация слайдов (опционально)

Из презентации `navigator.html` можно собрать анимированные слайды. Два выхода:

- **scroll-reveal** — уже встроен в `navigator.html` (анимация при листании в браузере/OBS), делать ничего не нужно. См. `workflow-broadcast-presentation.md`.
- **Пакет для монтажёра** — движок `tools/slide-animator/` (Remotion) **генерирует композиции автоматически из `navigator.html`** (любой тип слайда, без ручного кода):
  ```bash
  cd tools/slide-animator && ./render.sh {slug}          # весь ролик
  cd tools/slide-animator && ./render.sh {slug} 4 5 12   # только эти слайды
  ```
  Собирает в `scripts/{slug}/animation/`: `full/slide-NN.mp4` (готовые 16:9) + `poster/slide-NN.png` (референс) + `layers/slide-NN/` (слои PNG с прозрачностью, `00-bg` снизу).

### 🔴 Процесс-гейт (последовательность, соблюдать строго)

Движок гоняется **только по согласованному `navigator.html` и только один раз** — не жжём рендеры на черновиках:

```
1. Тексты сценария согласованы
2. Собран navigator.html
3. автор согласовал navigator.html (тексты финальные, вид ок)
4. ⛔ ГЕЙТ: спросить «navigator согласован — делать анимацию слайдов?»
5. автор: ДА → ./render.sh {slug} (один прогон)   |   НЕТ → пропускаем
```

⚠️ **Не забыть отдать монтажёру папку `animation/`** вместе со сценарием. В `montage-brief.html`/`tz.html` — секция **«🎞 Анимация слайдов»**: `full/` ставить как есть, `layers/` — для своей анимации (слои сложены по позиции, порядок `00…NN` снизу вверх).

> Скорость/ритм — `tools/slide-animator/src/timing.ts` (`SPEED`, >1 = медленнее). Гранулярность слоёв — `extract.mjs` (`CONTAINERS`).
